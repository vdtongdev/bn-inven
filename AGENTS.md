# BN-Inven engineering constraints

## Product scope
- BN-Inven digitizes a product catalog. It is not a stock, warehouse, purchasing, or transaction system.
- Do not add on-hand quantities. Package size is a descriptive attribute, not inventory quantity.
- Keep MISA integration in exporter profiles. The target product is not selected; never claim AMIS/SME compatibility without its official workbook and a successful trial import.

## Approved architecture
- React, Vite, TypeScript, Tailwind, `vite-plugin-pwa`; Python, FastAPI, Pydantic, SQLAlchemy, Alembic, SQLite WAL; openpyxl; Pillow.
- Modular monolith. API, worker, AI adapter, exporter, domain models and UI presentation stay separated by ordinary modules.
- SQLite and durable jobs share a persistent local volume. PostgreSQL migration remains a future database change; do not add Redis, Celery, Kubernetes, microservices, Next.js, LangChain, or LangGraph without a documented concrete need.
- AI responses are untrusted suggestions. Null uncertain values, retain raw results and provider/model/prompt metadata, require human approval, and never let AI create final workbook rows.
- Mock provider is the default local path. API secrets belong in environment variables and must not enter frontend bundles or Git.
- Item codes are generated by BN-Inven; barcode/model numbers are separate identifiers.

## Local workflow
- Backend: `cd backend; uv sync --extra dev; uv run alembic upgrade head; uv run uvicorn app.main:app --reload`
- Worker: `cd backend; uv run python -m app.workers.extraction`
- Tests: `cd backend; uv run pytest`
- Frontend: `cd frontend; npm install; npm run dev`
- Frontend check/build: `cd frontend; npm run build`; `npm test`
- Docker: copy `.env.example` to `.env`, configure the Caddy domain and Basic Auth hash, build images, run `docker compose run --rm api alembic upgrade head`, then `docker compose up -d`.

## Change conventions
- Add migrations for schema changes; production startup must not be used as an implicit migration mechanism.
- Run Alembic explicitly before API/worker startup. Only Caddy may publish public ports; do not add direct API or frontend host ports.
- Write backend tests for extraction schema, job idempotency/retry, approval gates, and export mappings.
- Restrict image types, bytes and decoded dimensions; generate server-side filenames; do not serve source images as public static files.
- Preserve the demo export disclaimer. Download success is not proof MISA import succeeded.
- PWA caches the application shell only. Do not promise offline AI recognition or background uploads after the app closes.
- Keep labels Unicode-safe and support Vietnamese text.
