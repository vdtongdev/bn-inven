# Deployment and recovery

## Local and VPS

Local development commands are in the root README. Docker Compose runs the API, a single worker, static frontend and Caddy TLS/authentication gateway. Copy `.env.example` to `.env`; never commit secrets. Set the real `DOMAIN`, a non-default `BASIC_AUTH_USER`, and a bcrypt `BASIC_AUTH_HASH` generated by `caddy hash-password`. The shared `bn_data` volume contains SQLite WAL files, original uploads and export files. After DNS points to the VPS and ports 80/443 are reachable, build, migrate, then start:

```sh
docker compose build
docker compose run --rm api alembic upgrade head
docker compose up -d
docker compose logs -f api worker caddy
```

### Current Docker build check (2026-10-29)

Earlier WSL Docker builds, both normal and `--network=host`, reached `RUN npm ci` and failed with `ERR_SSL_CIPHER_OPERATION_FAILED` during npm package downloads. After the user ran `wsl --update` and confirmed WSL/Docker registry response tests passed, the standard production build `docker build -t bn-inven-frontend-check .` from `frontend/` succeeded with exit 0. Container inspection verified `/srv/index.html`, `/srv/manifest.webmanifest`, and `/srv/sw.js`; `node` and `/web/node_modules` are absent from the final Caddy image. TLS verification remained enabled. The exact cause of the earlier failures is unknown; mirrored networking and WSL shutdown/restart were not tested, and no `.wslconfig`, source, proxy, or Docker daemon settings were changed.

Only Caddy publishes host ports 80/443. Its Basic Auth gate protects both the static frontend and API routes; API and web containers are reachable only on the internal Compose network. There is no unprotected Compose port for local browser access. Use the documented Vite and Uvicorn development commands for local work. A 2 GB VPS is only a starting estimate; observe memory during image processing and backups. Keep only one worker until lease/claim behavior is strengthened.

### Schema migrations

API and worker startup never create or alter tables. Run `docker compose run --rm api alembic upgrade head` after building the backend image and before starting either service. For local development, from `backend/`, run `uv run alembic upgrade head` before starting Uvicorn or the worker. A missing migration should fail visibly when a service accesses the schema; do not replace this step with `create_all`.

## Access, origins and secrets

The self-hosted deployment uses Caddy Basic Auth in front of both the static frontend and API. CORS is limited to configured origins and supports credentialed browser requests. Load any eventual AI provider key only on the backend. No shared application token is sent to or compiled into the browser.

### Optional OpenRouter vision extraction

Mock extraction remains enabled by default and requires no network key. To use OpenRouter, set `AI_PROVIDER=openrouter`, `AI_API_KEY` to a server-side key, and optionally `AI_MODEL` (the temporary, unvalidated test selection is `nvidia/nemotron-3.5-super-vl:free`) in the ignored root `.env`. Local backend settings load that root file; Compose passes its environment into API and worker containers. Never use a `VITE_*` variable for the key. `bn_inven` may be used as a dashboard label only; it is not sent as a request parameter.

The worker sends an EXIF-corrected, resized, re-encoded JPEG copy to the fixed OpenRouter chat-completions endpoint. It does not replace stored originals. Provider response JSON, model, prompt version and returned usage/cost metadata are stored with the extraction result for traceability. Permanent auth/request/schema failures are not retried; transient network, rate-limit and server errors use the job's bounded retries. Uncertain values remain null and all output remains a human-reviewed suggestion. The selected model's catalog accuracy and actual billed cost have not been validated. Keep `AI_PROVIDER=mock` for local tests and no-cost development.

## Cloudflare Pages

Build the `frontend/` directory with `npm ci`, build command `npm run build`, output directory `dist`. Caddy on the VPS does not protect a Cloudflare Pages origin. Configure Cloudflare Access (or an equivalent identity-aware gateway) for both the Pages site and the API hostname, or put the API behind an authenticated same-origin gateway. Set `VITE_API_BASE_URL` to that protected API endpoint and set backend `CORS_ORIGINS` to the exact Pages origin. Browser API requests include credentials; the gateway must support its cookie/session flow across the chosen origins. Do not put passwords, access tokens, or provider credentials in `VITE_*` variables. The self-hosted static option is the internal `web` service in Compose, reachable publicly only through Caddy.

The frontend's Node packages are build and test dependencies; production installs omitting dev dependencies contain no packages. The current full dependency audit reports four low findings in `vite-plugin-pwa`'s Workbox chain: `deepmerge@4.3.1` (`GHSA-gcqx-w48m-w2h4`) via `workbox-build` and `@rollup/plugin-node-resolve`. The npm audit fix suggestion downgrades `vite-plugin-pwa` to `0.2.1` as a breaking change, so that downgrade is not applied. The Caddy image copies only the generated `dist/` assets. Recheck the audit and upstream PWA/Workbox releases during dependency updates; this audit finding is not proof of exploitability in the static runtime.

## Backups

Stop API and worker briefly for a simple consistent SQLite snapshot, or use SQLite's backup API while online. Copy the database (including WAL-consistent state), `uploads/`, and `exports/` to off-site storage. Keep encrypted, versioned backups and test restores. A raw copy of only the main `.db` file while WAL is active can omit committed transactions.

Restore steps:

1. Install Docker on the replacement Linux VPS and copy the Compose/config files and protected `.env`.
2. Restore database and file directories into the `bn_data` volume with ownership allowing the containers to read/write.
3. Start one API and one worker; check `/api/health`, job queue state and a known photo/export.
4. Keep the prior host backup until restored catalog data and source images are confirmed.

Cloudflare R2 or another object store can be added behind a backup adapter later; it is not required for the initial deployment.

## Operations

`GET /api/health` reports process health. Logs go to container stdout with timestamps and severity. Monitor disk use, failed jobs, backup age and provider usage once a real provider is selected. HTTPS and authentication must be enabled before exposing the service publicly.
